# 换电脑继续发布

## 最短路径

1. 在新电脑克隆本仓库，或已有仓库执行 `git pull --ff-only`。
2. 打开[发布总表](发布总表.md)。只从“备稿未上传”开始，先查看平台是否曾手动发布同一组。
3. 在新电脑重新登录小红书。**登录状态不会通过 GitHub 同步，不要复制或上传旧电脑的 Cookie、二维码和服务日志。**
4. 告诉新电脑上的 Codex：

> 以这个仓库为主库，阅读 AGENTS.md、posts/发布总表.md 和 posts/publication_ledger.json。先 pull，核对平台已发和待发布列表，避免重传；保持每组5张、每两天北京时间20:00，按日期继续提交已复核的备稿。把相对图片路径转换为这台电脑的绝对路径。工具明确成功后才写回状态；结果不明先核对平台，不要重试发布。最后验证、提交、推送并核对远端 SHA。不要直接上传 P 开头的预分组。

## 当前可接续内容（2026-11-01 快照）

- P开头：新素材按题名粗分的五图预分组，未完成人工作品身份、视觉风格、历史去重与文案核验；全部未上传。其日期仅是容量占位，核验后才可转入正式 `schedule.json`。

以上仅为主库证据，不排除曾在其他客户端手动上传。换电脑接续时应重新核对当前平台，而不是把这份日期快照当成实时状态。

新批素材人工核验后，要在 `catalog/artworks.json` 对应条目保存非空 `review_verification`（核对日期、来源页、作品身份与历史去重结论），再设置 `approved`。只有修改状态而不保存核验依据，重建素材目录时仍会按自动初筛候选处理。候选转入正式分组后重新生成台账；预分组编号和占位日期不是永久分配，不能当作去重证据。

## 可移植的预览命令

需要 Python 3.9+（Windows 可能需要安装 `tzdata`），不需要旧电脑用户名或固定目录：

```bash
git pull --ff-only
python3 scripts/verify_library.py
python3 scripts/next_post.py --group 23
```

`next_post.py` 只打印文案、计划时间和**当前电脑**的五张图片绝对路径，绝不上传。输出可能含当前电脑目录，不要把输出保存到公开仓库。

实际提交需安装并启动[小红书 MCP](https://github.com/xpzouying/xiaohongshu-mcp)，在新电脑登录后由发布工具调用 `publish_content`。当前技能说明的定时窗口为1小时至14天，实际操作前要重新检查工具/平台限制；因此不能把一年后的占位日期当作已经上传成功。

## 每次发布的记录规则

1. 只使用正式备稿；未复核素材、P组、历史成功组、提交结果不明组禁止自动发布。
2. 不要在两台电脑同时发布。提交前 pull 并在主库登记、提交、推送“submission_in_progress”占用记录；不能成功推送时不要开始上传。
3. 发布工具明确成功：更新 `posts/schedule.json` 为 `scheduled_success`，保存计划时间、核对时间和经过脱敏的成功证据/笔记ID（如果工具提供）；不能标为“已核验发布”。
4. 超时或返回不明：保留 `submission_unknown`，先去平台查笔记和定时列表，不得盲目重传。
5. 到期后实际核对笔记页，才可填写 `publication_verified_at`。不要只因日期已过就标成“已发布”。
6. 更新新的平台检查记录，重建下表、验证、提交、推送。原始响应、token、账号资料、日志不得进入公开仓库。

```bash
python3 scripts/build_publication_ledger.py
python3 scripts/verify_library.py
git diff --check
```

然后审阅改动并提交、推送，比较 `git rev-parse HEAD` 与 `git ls-remote origin refs/heads/main` 的 SHA。GitHub 是最终主库。

## 文件分工

- `schedule.json`：正式文案、图片顺序、计划时间与平台提交证据。
- `publication_ledger.json`：全量逐图上传状态、历史组、候选组及余图，便于机器继续处理。
- `发布总表.md`：人能直接看的分组清单。
- `逐图上传状态.md`：全部1,456张图像版本的去向和审核状态。
- `platform_check.json`：最近一次脱敏的平台检查；它是快照，不是实时登录状态。

清单生成脚本不发布内容，也不确认平台状态；占位预分组不可自动批准。
